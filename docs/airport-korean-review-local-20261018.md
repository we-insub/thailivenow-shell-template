# 태국 공항 한국어 재검수와 메뉴 소속 수정

## 사용자 확정 목적·범위

한국 여행자가 태국 공항 메뉴에서 필요한 도착·출발·환승·시설·흡연·교통·항공사 창구 안내를 읽는다. 공항 안내를 읽다가 주소 접두사 때문에 지연·결항 메뉴로 소속이 바뀌면 안 된다. 지연·결항 메뉴의 향후 콘텐츠 재구성은 수행하지 않는다.

검수 대상은 한국어 공항 목록 1개, 수완나폼 5개(기존 시내 이동 대표 주소 포함), 돈므앙·푸껫·치앙마이 각 1개로 총 9개다. 외국어 원고·다른 공항·다른 주제의 본문은 재작성하지 않았다. 배포 요청은 없으며 로컬 반영 범위다.

## 메뉴·상위 연결

- 기존 헤더는 BKK 등 공항의 첫 주소만 태국 공항으로 인식했다. 하위 map/smoking/airlines는 airport-assistance 접두사를 따라 지연·결항을 선택했다.
- 공통 판별 `isKoreanAirportGuide`로 네 공항의 하위 주소와 수완나폼 시내 이동 대표 주소를 같은 공항 안내 소속으로 처리한다. 교통과 공항이 동시에 선택되지 않게 했다.
- 공항 상세의 상단 링크는 `/ko/airports/` 공항 목록으로 복귀한다. 중복되던 목록 복귀 링크 하나를 제거했다. 수완나폼 시내 이동의 상위 링크는 태국 공항 → 수완나폼 공항안내다.
- 공항 상세 WebPage의 breadcrumb 상위도 실제 공항 목록 대표 URL에 맞췄다. 지연·결항 허브의 선택 상태는 그대로 유지한다. 기존 대표 URL·페이지네이션·양방향 항공사/교통 연결은 보존했다.

## 시로코와 한국어 원문 대조

`natural-korean-copy.md`, 사용자 변경 전/후 전체 시로코 원문, `detail-template-rules.md`, 공항 시설 MD, SEO·내부 연결·날짜 계약을 읽었다. 소개는 시로코 소개의 구체적인 상황 설명, 이동은 하차→이동→목적지 안내, 조건은 적용 구역과 예외, FAQ는 직답 뒤 조건을 설명하는 방식으로 대조했다. 로맨틱한 경험이나 식사 표현은 공항 안내에 복제하지 않았다.

수완나폼 5개 페이지와 나머지 세 공항의 소개·기본정보·순서·시설·흡연·FAQ, 공항 목록, 항공사 창구 33행 및 기존 시내 교통 원고를 직접 읽었다. 기존 시내 교통의 요금·시간·승차 위치·조건을 다시 조사하거나 바꾸지 않았다.

| 발견한 표현·구성 | 반영 |
| --- | --- |
| 돈므앙·치앙마이 ‘KBank 공식 목록에 등록’ 문단과 FAQ | 위치를 알려주지 않는 독립 문단은 제거. 돈므앙 FAQ는 이미 확인된 은행·ATM 위치로 답변. 치앙마이에는 모르는 ATM 위치를 만들지 않음 |
| 푸껫 ATM 목록 등록 설명 | 확인된 국내선 2층 출발구역 위치를 먼저 안내하고 큰 외부 출처 링크는 본문에서 제거 |
| 수완나폼 도착·환승, 돈므앙 체크인·심사·게이트, 푸껫 도착·키오스크 반복 섹션 | 기존 이용 순서에 사실을 유지하면서 반복 소제목 정리 |
| ‘C게이트라는 표현만으로 위치를 단정하지 않았어요’ | D구역 매장을 찾아 현장 표지로 이동하도록 안내. C게이트 표현의 혼동 주의와 핀의 한계는 유지 |
| ‘정확한 좌표가 확보되지 않아 핀을 붙이지 않았어요’ | 독자가 이용할 현장 표지·출입문·안내 직원과 출입 구역을 설명. 미확인 출입문 핀을 생성하지 않음 |
| 항공사별 조사 경위·반복·딱딱한 종결 | 한국어 표시용 문구 16행을 따로 관리. 위치·시간·연락처·출처·실제 확인일 원본은 보존 |
| 공통 시설명이 영어로만 표시되거나 빈 시설번호 행 노출 | 일반 시설명 한국어 표시 보완, 원명 병기. 빈 ‘지도 표기’ 행 제외. 1,128개 원본 시설 행과 ID/층/시설번호 보존 |
| 핀이 없는 공항에서도 빨간 핀을 설명 | 실제 핀이 있을 때만 해당 설명 표시. 푸껫 FAQ는 G9 시설 핀을 정확히 설명 |

FAQ는 보이는 질문·답과 JSON-LD를 같은 내용으로 대조했다. 다른 세 공항의 시설 FAQ도 기존 항공사 FAQ와 한 FAQPage에 합쳤다. 기존 원고의 수치·구역·예외를 기준으로 작성했으며 새로운 공식 사실 조사는 수행하지 않았다.

## 전체 빌드 중 발견한 구조화 데이터 주소 형식

작업 중 전체 SEO 감사에 breadcrumb URL 검사가 추가되면서 기존 일부 페이지의 상대주소 73건이 검출됐다. 공통 page-seo에서 BreadcrumbList의 루트 상대주소에 실제 운영 도메인을 붙였다. 대상·명칭·순서·FAQ·날짜·화면 링크는 바꾸지 않는다. 잘못된 빈 값/프로토콜/비정상 URL 감사는 유지하며, 회귀 테스트는 메타 처리 뒤 상대주소 결함을 삽입하여 실제 감사가 계속 실패시키는지 확인한다. 다른 주제의 본문이나 목적지를 변경한 작업이 아니다.

## 증거와 결과

- 전후 사실 대조: 네 공항의 공식 출처·흡연 근거 URL·핀 좌표 동일. 항공사 33행의 location/hours/phone/email/sources/checkedAt/airlineId/airportIata 동일. 문장에 있는 서면 통지 7일/21일, 요일별 배정, 한국/태국 시간과 예외도 직접 대조.
- 전체 테스트 48개 통과. 전체 빌드 1,825페이지, SEO 오류 0개, 중복 제목·설명 0개, 기존 경고 134개. 날짜 테스트 9개 및 3,186개 bindings 감사 오류 없음.
- Pages 로컬 런타임 passed=true. 전체 사이트 디자인 감사 1,825페이지 issues=[].
- 초기 HTML 9개: 태국 공항 메뉴 하나만 선택, 공항 복귀 URL, H1 하나, FAQ와 본문 일치, 출처 소개식 독립 ATM/S&P 문단 제거 확인. 지연·결항 허브는 지연·결항 메뉴를 유지하는지 확인.
- 실제 브라우저 PC에서 수완나폼 1~5 및 다른 세 공항 이동 후 공항 메뉴 유지·가로 넘침 없음 확인. 좁은 모바일 화면의 실제 CSS viewport 433px에서 9개 모두 선택 메뉴 유지·가로 넘침 없음 확인(요청한 390px override의 실제 반환값을 기록).
- 한국어 ‘의료실’ 검색으로 푸껫 시설 2행 확인, G9 흡연구역 버튼의 지도 전환 확인. 이전 휠·드래그·시설 필터·출처 접기 기능을 유지한다.
- `artifacts/airport-korean-review-20261018/`에 전후 원고 대조용 before-guides.json, fact-checks.json, html-checks.json, PC/모바일 탐색 JSON과 화면 PNG를 보관했다. 자동 단어 검색만으로 한국어 의미 검수를 대신하지 않았다.

이번 작업으로 커밋·푸시·운영 배포·색인 제출·검색 노출·AI 인용을 수행했다고 보고하지 않는다. 다른 작업의 미커밋 소스와 QA, 기존 승인 날짜와 사용권 보류 조건을 보존한다.
