# ThaiLiveNow 연관 페이지 연결·생성 검수 계약

2026-10-17 사용자 요청. 재팬·코리아라이브나우에서 확정한 관계 기반 연결 기준을 ThaiLiveNow의 실제 구조에 맞춰 적용한다. 모든 지원 언어·시장과 신규·기존 페이지에 적용하며, 페이지네이션(목록의 이전/다음 쪽)과 별개의 상위·하위·관련 페이지 연결 기준이다. [AGENTS.md](../AGENTS.md), [SEO 규칙](page-seo-rules.md), [상세 템플릿](detail-template-rules.md), [언어·시장](language-settings.md), 날짜·공개 범위·기존 검증·배포 관문을 함께 유지한다.

## 1. 언제 자동으로 작업 범위에 포함하는가

페이지·상세·콘텐츠 데이터·HTML을 새로 생성하거나 공개할 때, 기존 페이지의 장소·도시·지역·노선·일정 구성·정본 URL·언어 대응·공개 상태를 변경할 때 적용한다. 관계를 만드는 원고·데이터·Astro 템플릿·가져온 HTML 조각을 생성하는 경우도 포함한다. 관련 상세가 나중에 공개되면 기존 상위·관련 페이지의 연결을 함께 재평가한다.

조건이 성립하면 별도 사용자 재지시 없이 필요한 링크 반영과 검수를 같은 작업에 포함한다. 새 상세만 생성하고 기존 상위·관련 페이지의 들어오는 링크를 빠뜨리면 공개 준비 완료로 보지 않는다. 파일 생성·업로드·사이트맵 등록만으로 실제 내부 연결을 대신하지 않는다. 관련성을 검토하되 모든 페이지에 시설·일정 링크를 일괄 삽입하지 않는다.

## 2. 관계별 판단 기준

| 관계 | 성립 근거와 적용 |
| --- | --- |
| 상위 허브·카테고리·도시 목록 ↔ 상세 | 실제 소속 ID·분류·공개 라우트를 대조한다. 새 공개 상세는 해당 상위 초기 HTML에서 찾을 수 있어야 하고 상세에서도 상위로 돌아갈 수 있어야 한다. 전역 메뉴·푸터만으로 충족하지 않는다. |
| 도시·카메라 ↔ 여행·시설 안내 | 실제 촬영 대상·장소 ID·확인된 지역 소속과 독자의 다음 질문이 맞는 경우 관련 안내 블록에서 연결한다. 촬영 장소와 설치 위치를 구분하며 같은 도시라는 이유만으로 전체 시설을 나열하지 않는다. |
| 명소·루프탑·전망대·해변 ↔ 교통 | 실제 이용 노선·역·정류장·선착장·공항 이동과 확인된 접근 근거가 있을 때 연결한다. 역·선착장 상세에서도 실제 관련 시설을 검토한다. 직선거리로 보행 시간이나 탑승 관계를 만들어내지 않는다. |
| 공항 ↔ 항공사·노선·공항 이동 | 실제 운항·이용 구간·출도착 공항·시장별 조건과 공개 라우트를 대조한다. 공항→시내와 공항↔공항을 혼동하지 않는다. 다른 시장 항공사·연락처·보험 조건을 복제하지 않는다. |
| 일정·추천코스 ↔ 실제 구성 장소 | 실제 공개된 일정이 있고 방문 장소 ID·순서·조건이 확인된 경우에만 양방향으로 연결한다. 같은 도시의 모든 일정을 해당 명소 포함 일정으로 소개하지 않는다. |
| 다른 기간·대안 안내 | 같은 여행 결정에서 비교할 실제 이유와 다른 구성이 있을 때만 연결한다. 제목만 다른 중복 페이지를 추가하지 않는다. |
| 음식·쿠폰·입국·안전·운영 안내 | 페이지의 질문과 실제 적용 조건에 직접 도움이 되는 관련 안내를 검토한다. 약관·개인화 화면까지 여행 일정 링크를 무조건 삽입하지 않는다. |

ThaiLiveNow에는 현재 도시별 루프탑·전망대 허브/시설 상세, 해변, 명소, 공항·항공편, 교통 노선·역·터미널·선착장, 카메라 등 서로 다른 구조가 있다. 실제 존재하는 구조와 승인된 공개 범위를 사용한다. 일본의 47개 도도부현·1~4박 일정 구조를 복제하거나 존재하지 않는 태국 일정·번역을 생성하지 않는다.

## 3. 생성·수정 작업의 실행 순서

1. 대상 질문·언어·시장·공개 범위와 변경 파일/URL을 정하고 기존 완료 근거를 보존한다. 새 목적·메뉴·대상이 불명확한 부분은 AGENTS의 질문 규칙을 따른다.
2. 실제 데이터·라우트에서 페이지/장소/도시/부모/노선/역/선착장 ID, 구성 장소, 언어·시장, 정본 URL, 공개 상태를 읽는다. `src/data/rooftops.json`과 `/ko/rooftops/cities/[city]` → 시설 상세처럼 실제 데이터·경로를 근거로 삼는다. 루프탑의 `publicationStatus` 등 유형별 실제 공개 필터도 확인한다. 필드가 없으면 승인된 기존 사실로 관계를 수동 대조하고 근거를 기록한다. 이름 유사도·지역명·모델의 추측으로 관계를 확정하지 않는다.
3. 관계가 성립하는 후보와 필요한 양방향 링크를 정한다. 새 상세뿐 아니라 영향을 받는 기존 상위·관련 페이지를 같은 변경 범위에 포함한다. 관계가 없으면 해당 없음, 불명확하면 보류 이유를 기록한다.
4. 실제 존재하는 같은 언어·시장 공개 정본으로 초기 HTML의 `<a href>`를 출력한다. 승인된 공통 컴포넌트·구조화 매핑을 재사용하며, 새 파일·가져온 HTML 조각도 최종 생성 HTML에서 실제 링크가 되는지 확인한다. 공개 상세의 발견 경로를 클릭 후 JS 삽입이나 지도 팝업 하나에만 의존하지 않는다.
5. 기존 검수 본문·소개·FAQ·사진·사실·수치·예외·출처·확인일·완료 기록을 보존한다. 필요한 관련 안내 블록과 링크 문구만 추가한다. 링크 작업을 본문 전체 재집필·공식 사실 재조사로 확대하지 않는다.
6. 생성 HTML의 링크·앵커·언어·정본·사이트맵과 관련 PC·모바일 탐색을 검수하고, 기존 필수 검사 및 승인된 배포 절차를 따른다. 공개 코드·공통 컴포넌트를 바꾸면 영향받는 전체 URL·언어를 범위로 삼는다.

## 4. 언어·URL·공개 상태

실제 지원 경로는 `ko`, `ms`, `zh-cn`, `en`, `en-in`, `ru`, `ja`, `en-gb`, `en-us`, `es`, `zh-tw`다. 한국어는 `/ko/`이며 JapanLiveNow의 `/kr/`를 사용하지 않는다. 최신 지원 목록과 공개 정책은 실제 소스 및 language-settings·page-seo-rules와 대조한다.

- 같은 언어·시장의 실제 대응 상세를 선택한다. 대응 페이지가 없으면 검색용 관련 추천 링크를 생략·보류하고 기록한다. 언어 접두사만 바꾸거나 한국어·공통 영어 홈으로 조용히 대체하지 않는다. 기존 서비스의 언어 선택 동작은 별도 정책으로 보존한다.
- 링크 문구는 해당 언어로 대상 장소·이용 목적·필요한 기간을 설명한다. 주변 문맥으로 명확하면 짧게 쓰고 같은 키워드를 반복하지 않는다. 링크 문맥과 목적지가 맞는지 사람이 읽는다.
- URL은 실제 대표 경로·존재하는 앵커를 사용하고 canonical·사이트맵·공개 응답과 맞춘다. 별칭·리디렉션·404·준비 중·held·비공개·미완성 번역·noindex를 검색용 관련 상세로 추천하지 않는다. 저장·비교 등 기존 서비스 탐색 링크의 역할은 별도로 유지한다.
- 기존 한국어 우선·시범 공개·보류 등의 유형별 최신 승인 범위를 지킨다. 관련 링크 규칙을 이유로 보류 자료를 공개하거나 새 언어판·일정을 발행하지 않는다.

## 5. 검사와 완료 판정

| 검사 | 필요한 증거 |
| --- | --- |
| 상위↔상세 | 기존 상위 초기 HTML의 실제 상세 링크와 상세의 상위 복귀 링크 |
| 필수 관련 연결 | 관계별로 필요한 들어오는/나가는 링크가 영향받는 실제 생성 HTML에 있는지 확인 |
| 장소·교통·일정 | ID·실제 이용 구간·구성 장소·공개 필터와의 일치, 수동 대조 근거 |
| URL·언어·정본 | 대상 응답·앵커·같은 시장·canonical·사이트맵 및 색인 정책 일치 |
| 사람의 검수 | 링크 문구·문맥·기존 사실 보존, PC·모바일의 안내 블록·실제 이동 |
| 자동 검사 | 기존 SEO·사이트 디자인·날짜·전체 테스트/빌드·런타임 관문과 변경 영향 검사 결과 |
| 배포·검색 | 로컬 검수, 커밋/푸시, 실제 운영 배포/응답, Google 수집·색인·검색 노출 각각의 상태 |

`node scripts/audit-site-design.mjs <빌드경로>`의 기존 메뉴·내부 링크 검사와 SEO 감사를 유지한다. 그 검사만으로 관계 기반 필수 링크의 누락·문맥·명소 포함 관계까지 검증됐다고 주장하지 않는다. 관계 자동 생성·추가 검사의 미구현 항목은 수동 반영·대조하고 **수동 검수/자동화 미구현**으로 기록한다. 새 자동화를 구현한다면 실제 실패 사례와 빌드 연결·전체 영향 범위를 검증한다. 파일·스크립트·체크박스 존재는 실행 증거가 아니다.

사이트 연결 검사 통과는 Google의 수집·색인·특정 키워드 노출 완료가 아니다. 미확인 항목은 통과로 표시하지 않는다. 실제 페이지 변경은 기존 승인 범위의 검증·푸시·정식 배포 및 운영 확인까지 적용하되, 문서만 바꾸는 작업은 필요한 문서 확인·승인된 커밋·푸시로 인계하고, 공개 반영이 필요하지 않은 사이트 배포·색인 신청을 관성적으로 실행하지 않는다.

## 6. 작업 MD의 필수 기록

기존 브리프·작업 MD에 대상 파일/URL·페이지 ID·언어/시장·질문·공개 범위, 상위와 실제 들어오는 링크의 출발 URL, 관계별 대상 URL/ID/근거, 필수·조건부·해당 없음·보류 이유, 기존 페이지 변경 범위를 남긴다. 링크 문구·생성 HTML·앵커·canonical·사이트맵 검사, 자동 검사 구현/실행 여부·수동 검수·PC/모바일 범위, 보존한 본문/완료 근거와 소스 상태, 커밋·푸시·배포·수집·색인·노출 상태를 기록한다. 별도 중복 원장을 의무로 만들지 않는다.

이 계약 저장은 앞으로 승인된 제작·유지보수에서 조건이 성립할 때 연결 반영과 검수를 자동으로 작업 범위에 포함한다는 뜻이다. 기존 전체 페이지 일괄 수정·연관 링크 엔진 구현·새 공개 범위·배포·색인·예약 자동화 완료를 뜻하지 않는다.
