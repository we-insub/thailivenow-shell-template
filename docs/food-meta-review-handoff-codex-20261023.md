# 음식 섹션 메타 설명 점검 — Codex 인계 (2026-10-23)

> **완료 (2026-10-23):** Codex가 코리아라이브나우 작업에 쓰이고 있어, 이 점검은 Sonnet 서브에이전트 7개로 끝냈다(영어 4종·말레이어·러시아어·스페인어, 49개씩). 이 문서는 점검 기준으로 보관한다. 아래 발견 기록은 비어 있다.

## 요청 배경

`/ko/food/` 49쪽을 10개 언어로 미러링한 작업의 후속이다. 일본어·중국어(간체·번체) 메타 설명은 이미 점검해 고쳤다. **영어 4종(`en`, `en-us`, `en-gb`, `en-in`)·말레이어(`ms`)·러시아어(`ru`)·스페인어(`es`) 7개 팩의 메타 설명은 아직 점검하지 않았다.** 이 문서는 그 점검을 Codex가 이어받기 위한 작업 목록과 주의점이다. 구조와 작성 규칙은 [food-localization-brief-20261023.md](food-localization-brief-20261023.md)를 먼저 읽는다.

## 대상 파일과 범위

- 팩: `src/data/food-localized/<언어>.json`의 `meta` (언어당 49개, 합계 343개). 키는 `/<언어>/food/…/` 경로다.
- 저장 위치: 검수 후 `node scripts/merge-food-meta.mjs <언어>`로 `src/data/meta-descriptions/<언어>.json`에 복사한다. 두 곳이 어긋나면 `tests/food-localization.test.mjs`가 실패한다.
- 점검 대상은 메타 설명뿐이다. 본문·이미지·URL·구조는 바꾸지 않는다. 메타 설명 점검 중 본문 오류를 발견하면 고치지 말고 아래 "발견 기록"에 적는다.

## 점검 항목

각 메타 설명을 같은 페이지의 팩 본문(`dishes`, `fruits`, `cities`, `pages` 아래 해당 항목)과 나란히 읽고 판단한다.

1. **본문에 없는 표현**: 가격·시간·효능·조건·할랄/채식 여부·환율 환산·여행 유형(예: 혼자 여행)처럼 본문이나 FAQ에 근거가 없는 말을 지운다.
2. **불필요한 맺음 문구**: 글자 수를 채우려고 붙은 일반적인 마무리("…에 어울립니다", "…를 참고하세요", "페이지에는 공식 출처도 있어요")를 지우고, 그 페이지의 FAQ·팁·구매 안내에 있는 사실로 바꾼다.
3. **반복**: 같은 사실이 한 설명 안에서 두 번 나오거나, 문장이 쉼표로 길게 이어지면 정리한다.
4. **핵심 검색어 위치**: 한·중·일은 앞 60자, 그 밖의 언어는 앞 120자 안에 장소·대상과 핵심 검색어가 있어야 한다([AGENTS.md](../AGENTS.md)의 메타 설명 기준과 작성 절차).
5. **시장 맞춤**: `en-us`는 미국 철자, `en-gb`는 영국 철자, `en-in`은 인도 독자의 관심(동물성 조미료·채식 조건)을 한국판 본문에 있는 범위에서만 앞세운다. `en`은 국가색이 없는 영어, `ms`는 말레이시아 말레이어(인도네시아어 어휘 금지), `es`는 스페인 스페인어다.
6. **고유명·기관명**: 아래 표기 기준과 어긋나는 것을 맞춘다.
7. **길이·형식**: 공백·문장부호 포함 150~199자, 완전한 문장, 큰따옴표·이모지·HTML 금지, 같은 언어 안에서 중복 금지. 길이는 `node scripts/validate-food-pack.mjs <언어>`가 검사한다.

## 이미 고친 것 (같은 문제가 남았는지 찾아볼 것)

- 본문에 없는 말이 들어간 사례: "ロティ菓子", "ひとり旅", "冰淇淋"처럼 근거가 확인되지 않은 표현. 예외로, 두리안의 아이스크림·디저트 활용은 본문에 있어서 유효하다.
- 설명이 길이를 채우려고 뒷부분에서 같은 사실을 반복하거나 "…하면 더 좋아요" 식 문구를 붙인 사례.
- 도시 수 오류: 과일 가격 페이지는 **6개 도시**(방콕·치앙마이·푸껫·아유타야·콘깬·핫야이)이다. 5개로 쓰인 곳이 있었다.
- 임의 음역. 아래 표기를 따른다.

## 점검이 필요한 7개 팩의 알려진 주의점

- `en-us`: 에이전트가 "Tom Yum Goong", "Som Tam (Papaya Salad)", "Thai Mandarin Orange"처럼 `food.json` 표기와 다른 이름을 쓴 곳이 있다. 설명 안에서 한 이름으로 일관되는지 본다.
- `en-gb`: 디저트를 "pudding"으로 쓴 곳이 있다. 설명의 의미가 맞는지 본다. `Edor`, `Rong Rian` 라벨은 위 기준으로 이미 통일했다.
- `en-in`: 한국판의 채식·동물성 조미료 정보 범위를 넘어 새 채식 주장을 만들지 않았는지 본다.
- `en`: 국가색이 섞이지 않았는지 본다.
- `ms`: 메타 3개에서 "sekilo"로 줄여 쓴 곳이 있다. 가능하면 "sekilogram"로 되돌리고 길이를 다른 사실로 맞춘다. 인도네시아어 어휘가 섞였는지 본다.
- `ru`: 도시명을 "Еда в городе {name}"처럼 고정 템플릿으로 쓴 곳은 격변화가 안 맞을 수 있다. 메타에서는 자연스러운 형태를 쓴다.
- `es`: "Mes {n}" 같은 달력 문구는 월 이름으로 대체돼 더 이상 쓰이지 않는다. 메타는 해당 없음.

## 작업 방법과 검증

1. 시작 전에 `git status`로 다른 미커밋 작업(명소·루프탑·언어 선택기 등)을 확인하고 섞지 않는다. 음식 작업 파일은 `docs/food-localization-brief-20261023.md`의 구조 절과 이 문서에 나온 경로다.
2. 팩의 `meta`만 고친다. 고친 뒤 `node scripts/validate-food-pack.mjs <언어>`가 0 오류인지 확인한다.
3. `node scripts/merge-food-meta.mjs <언어>`로 `meta-descriptions`에 반영한다.
4. `npm test`가 150개 통과하는지 확인한다.
5. 전체 `npm run build`(SEO·날짜·편집 감사 포함)는 이번 수정을 모두 반영한 뒤 한 번 실행한다. 로컬 작업 폴더의 다른 미커밋 변경 때문에 결과가 흐려지면 깨끗한 HEAD 사본에 변경만 얹어 검증한다.
6. 작업 기록은 이 문서의 "발견 기록"에 이어 적는다.
