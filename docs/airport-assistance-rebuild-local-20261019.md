# 지연·결항·수하물 한국어 로컬 개편

사용자 승인: 2026-10-19. 새 자료조사 없이 기존 데이터를 사용해 한국어 허브·상세를 자연스러운 안내로 재구성한다. 운영 배포·커밋·푸시·색인 요청은 하지 않는다. 타 작업의 변경은 보존한다.

## 목적과 확정 범위

- 메뉴는 지연·결항. 한국↔태국 이용자가 항공편 또는 위탁수하물 문제 발생 시 지금 할 행동, 항공사 신고·확인서, 지원·보상·보험 순서로 해결하도록 한다.
- 국가별 허브에는 그 국가에 필요한 내용을 선별한다. 한국어 허브에 다른 국가 항공편·보험사를 나열하지 않는다. 일반 공항 시설·카운터·시간표 탐색은 태국 공항과 기존 상세를 사용한다.
- 국적과 운항사는 다르다. 한국어·영어 이름과 항공사 코드(기존 편명에서 추출)로 검색하고, 한국어 자료가 있는 항공사는 한국어 상세에 연결한다. 모든 국가에서 이용할 공통 영문 항공사 검색은 별도 /en/airport-assistance/에 둔다. 기존 10시장 자료에 존재하는 항공사만 다루며 전 세계 모든 항공사 확보로 보고하지 않는다.
- 1차 작업은 한국어 허브와 연결된 10항공사·36안내 상세의 구조·한국어·내부 연결 검수다. 공항별/노선/공항쌍 기존 URL과 원고는 보존한다. 다른 국가 허브의 전체 본문 재작성은 이번 범위가 아니다.

## 구조·본문 계획

허브: 상황별 첫 행동 4개 → 항공사 이름·코드 검색과 상황 선택 → 증빙 준비 → CAAT 지원·보상과 보험 청구 구분 → 필요한 공항 안내. 국가별 목록·모든 전화·카운터·노선·원고 목록을 처음부터 펼치지 않는다.

상황 상세: 질문에 대한 직답 → 실제 행동 순서 → 항공사마다 다른 절차·기한·서류 → 필요한 항공사 검색 → FAQ → 관련 다음 행동 → 닫힌 공식 출처. 항공사 상세: 사고 접수·확인서가 먼저, 일반 공항 카운터와 노선은 별도 펼치기. 기존 사실·기한·기산점·예외·출처·확인일·전화·메일·추적값 보존. 기존 좋은 한국어는 유지하고 조사 메모·명사 나열·역할 불명확 문장을 행동으로 풀어쓴다.

## 연결·색인 계획

- 기존 URL 보존. 한국어 허브↔4상황↔해당 항공사↔항공사별 신고/확인서의 초기 HTML 실제 링크를 만든다. 해당 항공사와 관계없는 상세를 묶지 않는다. 보험사 3곳은 보험 안내에서 연결하고 출처 목록은 접는다.
- 공통 영문 검색은 별도 언어임을 명시. 그 검색 결과를 각 국가의 대표 추천 항공사로 무조건 추가하지 않는다. 없는 번역을 같은 주제의 hreflang으로 만들지 않는다.

- 제목·H1·설명·본문·FAQ/JSON-LD 일치, 중복·깨진 내부 링크/앵커·noindex/X-Robots 검수. 전체 테스트·전체 빌드/SEO·날짜 감사·실제 Pages 로컬 런타임·PC/모바일/키보드 검색 기능 검증.
- 로컬 완료 후 운영 배포 승인 → 운영 정본·사이트맵 확인 → 필요 시 별도 사용자 승인으로 검색엔진 요청. 로컬 검증은 실제 수집·색인·노출 증거가 아니다. 향후 배포 14일 뒤 GSC/네이버의 노출·클릭·색인 상태를 수동 비교하고 AI 인용은 별도 실제 응답으로 확인한다. 자동 일정은 생성하지 않는다.

## 반영 결과와 원고 대조

한국어 허브는 국가·전화·노선·원고 목록의 나열을 없애고, 네 가지 상황의 첫 행동 → 항공사 검색 → 보관할 증빙 → 항공사 지원·보상과 보험의 구분으로 재구성했다. 네 상황과 항공사 상세, 개별 신고·확인서, 보험사 안내의 실제 초기 HTML 링크를 양방향으로 연결했다. 10항공사 상세는 목적별 신고·확인서가 먼저 나오고, 수하물 문의/예약·발권·사무실/일반 체크인은 각각 별도 접기 안에 구분했다. 기존 44노선과 일반 수속 자료도 별도 펼치기로 보존했다. 공항 시설·카운터·심야 이동 6개 기존 URL은 보존하면서 태국 공항 메뉴·상위 링크를 따르게 했다.

한국어 원본 JSON은 작업 전 파일과 바이트 단위 동일하다(SHA-256 `f570977552e4c9a84384186beac1a29c033e3e14e0d341132468cd8bea9f034e`). 표현 수정은 별도 한국어 표시 데이터로 적용했다. 36가이드 전체의 도입·본문·FAQ를 대조하고, 26가이드에 문장/제목/핵심 강조 수정, 10항공사에 업무별 도입을 적용했다. 이미 자연스럽고 구체적인 문장은 유지했다. 111개 본문 구간, FAQ 80개, 서비스 73건의 전화·메일·장소·시간, 44노선 링크가 최종 HTML에 보존됨을 확인했다. 수정 구간의 기존 숫자가 빠진 사례는 없다. 공식 출처·확인일·신고기한·기산점·예외를 새 사실로 교체하지 않았다.

시로코 기준 대조: 추상적인 “안내를 확인하세요”를 반복하지 않고 무엇을 준비해 어느 곳에 신고할지 먼저 썼다. 예를 들어 아시아나 수하물 안내는 파손 자료 → 미도착 신고 → 도착 공항 이메일의 역할을 구분한다. 에어프레미아는 변경 전 출발일로 확인서를 찾는 행동을 설명하고, 보험사 안내는 가입 특약과 서류 제출 경로를 나눈다. 기한·기산점·본인 확인·운항사 적용 조건을 짧게 강조하고, 긴 공식 출처는 기본 닫힘으로 유지했다. 목차와 본문 번호 출처는 추가하지 않았다.

기존 자료의 서로 다른 안내는 임의로 통일하지 않았다. 에어부산 예약센터 시간의 자료별 차이, 이스타·에어부산의 일반 안내와 국제약관 신고 기산점, 아시아나의 서비스별 수속 조건 등은 기존 적용 범위와 원문을 유지한다. 미확인 사실을 조사·확정한 작업이 아니다. CAAT 상세의 기존 승인 본문·적용 조건은 보존했다.

## 추가 요청: 한국 출발공항 카운터·문의처 하위 분리 (2026-10-19)

사용자 요청으로 기존 한국 출발공항 서비스 40건(ICN 26, PUS 13, TAE 1)을 `/ko/airport-assistance/departure-airports/` 하위 페이지에 배치한다. 기존 허브의 40건 나열은 복구하지 않고 `#services` 안내 블록에 하위 페이지로 가는 실제 링크만 둔다. 새 조사는 하지 않으며 한국 시장 자료만 사용한다. 다른 언어·국가 페이지에 한국 창구를 추가하거나 번역하지 않는다.

새 페이지의 중심 질문은 “한국에서 태국행 비행기를 탈 때 어느 창구에 가거나 어디에 연락해야 하나요?”이다. 공항별로 체크인/발권·사무실/수하물·유실물/원격 고객센터를 분리하고 공항·업무 선택 필터를 제공한다. 비어 있는 항목은 만들지 않고 해당 조합의 자료가 없는 경우를 알린다. 기존 연락처 역할, 창구·시간·설명·공식 출처·개별 확인일을 보존하며 출처 확인일과 수정일을 구분한다.

상위 `/ko/airport-assistance/` → 새 하위 → 기존 `/ko/airport-assistance/airports/icn/`, `/pus/`, `/tae/`에 연결한다. 세 기존 공항의 상단 복귀와 구조화된 breadcrumb도 새 상위에 연결하되 기존 URL은 보존한다. 실제 관계가 있는 항공사 신고·확인서와 태국 공항 안내로 연결한다. 신규 페이지는 독립된 한국 출발공항 모음 검색 의도로 자기 canonical·index·사이트맵을 사용하며 다른 국가 대응 페이지/hreflang은 생성하지 않는다. 초기 HTML에 세 공항과 40건을 모두 렌더링하고 필터는 추가 색인 URL을 만들지 않는다.

## 추가 요청: 허브 사용 흐름과 검색 진입 개선 (2026-10-19)
