# 검증된 전체 결과물을 보존하는 부분 배포

2026-10-15 사용자 승인. 목적은 기존 본문·URL·디자인을 유지하면서 수정한 페이지의 렌더링만 반복하는 것이다. 운영 도메인은 https://thailivenow.com, Pages 프로젝트 thai-live-now/main이다. 새 일정이나 색인 요청을 만들지 않는다.

## 안전한 범위

`npm run release -- --commit <SHA> --date YYYY-MM-DD --output <새 경로>`가 커밋의 git archive를 격리 디렉터리로 추출한다. 현재 디렉터리의 미커밋·미추적 변경은 읽어 배포하지 않는다. 의존성은 lockfile로 npm ci 한다. 커밋에 포함할 변경은 작업자가 먼저 명시적으로 선별한다.

첫 실행은 전체 빌드다. 성공한 운영 배포를 실제로 확인한 뒤 `npm run release:verify -- <결과 경로>`로만 다음 기준을 활성화한다. 기준에는 배포 SHA·불변 배포 URL·전체 파일 SHA256·Vite 실제 의존성 그래프 해시가 있다. 기준 파일이나 그래프가 바뀌면 거부하며 현재 운영의 날짜 JSON 커밋도 일치해야 한다. 오래된 기준으로 운영을 덮어쓰지 않는다.

다음 실행:

```
npm run release -- --commit <SHA> --date YYYY-MM-DD --baseline <검증된 결과 경로> --output <새 결과 경로>
```

Vite가 실제 해석한 정적·동적 import/glob 그래프에서 변경 소스를 사용하는 라우트만 선택한다. 동적 라우트의 데이터는 해당 라우트가 생성하는 페이지 전체를 대상으로 한다. 개별 JSON 레코드 한 개의 영향까지 추정하지 않는다. 공통 컴포넌트면 모든 사용 라우트를 재생성한다. 새/알 수 없는 소스, 소스 삭제, 패키지/설정/Functions/빌드 스크립트/날짜 기록 변경은 전체 빌드로 전환한다. 공개 자산·문서만 바뀌면 HTML 렌더링은 0개일 수 있다.

Astro 컴파일과 경로 열거는 전체에 대해 유지한다. 빌드 전용 middleware가 비대상 경로를 빈 204로 종료해 본문 렌더링과 HTML 재생성을 생략한다. 선택 경로의 결과와 정적 자산을 이전 전체 트리에 합친다. 기존 해시 자산을 보존하므로 재사용 HTML의 CSS·JS가 사라지지 않는다. 삭제된 공개 자산만 명시적으로 제거하며 페이지 삭제는 전체 빌드다. 전체 트리에서 sitemap과 robots를 재검사·생성한다.

## 그대로 유지하는 필수 관문

- 전체 tests/*.test.mjs, 기존 SEO 회귀 테스트. 실패하면 중단한다.
- 전체 모드의 `npm run build`는 기존 명령 그대로 실행한다. 부분 모드는 Astro의 선택 렌더링 후 **합친 전체 HTML**에 기존 SEO 감사와 날짜 prepare·감사를 실행한다. 중복 제목·설명·canonical·hreflang·색인·JSON-LD 검사 범위를 줄이지 않는다.
- 변경되지 않은 결과물 해시 보존, 기준 해시/그래프 변조 방지, 실제 Pages 로컬 런타임에서 11개 언어·날짜 기록·API/자산·preview noindex 검사.
- 날짜는 SITE-DATES.md 계약을 유지한다. 배포일을 실제 확인일이나 수정일에 복사하지 않는다.
- 변경 화면의 PC·모바일·기능은 운영자가 실제로 검수한다. 빌드 시간 단축을 전체 자동 검사 생략으로 설명하지 않는다.

## 배포·승격

동일 명령에 `--deploy`를 지정하면 모든 관문 통과 후 격리한 동일 소스의 Functions와 결과물 전체를 공식 Wrangler로 main에 업로드한다. 업로드 직전 운영 기준 커밋을 다시 검사한다. Cloudflare가 하나의 전체 배포로 전환하므로 서비스 중 페이지 일부가 빠지는 방식이 아니다. CLI의 파일 해시 재사용을 함께 이용한다. 업로드 성공만으로 기준을 승격하지 않는다.

실제 운영 응답·지원 언어·공통 날짜 JSON·주요 자산·preview noindex를 `release:verify`로 확인한 뒤 결과물을 다음 기준으로 보관한다. 실패한 후보는 기준이 될 수 없다. 서로 다른 운영자가 동시에 배포하지 않도록 릴리스 하나씩 진행한다. Cloudflare Direct Upload에는 원자적 compare-and-swap이 없으므로 업로드 도중 외부 배포가 발생하면 실제 운영 커밋 불일치로 승격하지 않고 새 기준에서 재검증한다.

결과 경로의 release.json과 graph.json 및 dist는 한 세트다. QA와 결과물을 덮어쓰거나 다른 작업의 기록을 지우지 않는다. 보관 기준이 없으면 전체 빌드를 수행해 새 기준을 만든다. 롤백은 Cloudflare 이전 성공 배포를 활성화하고 그 성공 기록에 맞는 기준을 다시 선택한다.
