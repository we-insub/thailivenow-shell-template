# 명소·교통 상세페이지 공통 템플릿 규칙

모든 날짜 표시는 `SITE-DATES.md`와 공통 `src/components/RuntimeDate.astro`를 따른다. 실제 자료 확인일·링크 점검·콘텐츠 수정일은 배포일과 구분한다. 정확한 기록이 없으면 미확인으로 유지하고 기존 날짜 외 사실·출처·예외는 보존한다. 신규 페이지는 `page-generation-date-contract.md`도 반드시 적용한다.

## 모든 상세페이지 필수 기준 — 시로코 (2026-10-14 사용자 확정)

이 절은 과거 목차·개별 템플릿·임시 홀딩 기록보다 우선한다. 새 상세페이지 작성과 기존 상세페이지 수정은 주제·언어에 관계없이 승인된 시로코 상세페이지를 기준으로 한다. 현재 로컬 `src/components/RooftopDetail.astro`와 `src/data/rooftops.json`의 시로코가 기준이며, 운영 참고 URL은 https://thailivenow.com/ko/rooftops/sirocco/ 이다.

- 적용 범위: 명소·루프탑·해변·공항·교통수단·노선·역·터미널·선착장·항공사·지연/결항·수하물·보험·앱 이용 안내 등 모든 상세페이지와 모든 지원 언어.
- 구성: 페이지 제목과 자연스러운 소개 → 해당 주제에서 가장 필요한 지도/사진/이용 안내 → 기본 정보 → 실제 이용 순서와 상세 조건 → FAQ → 관련 상세 연결 → 공식 출처. 공항은 층별 지도와 도착/출발/환승·편의시설, 교통은 이동 지도와 승차 위치를 먼저 배치한다. 장소에 없는 항목을 억지로 복제하지 않는다.
- 목차는 만들지 않는다. 기존 상세를 수정할 때도 목차를 제거한다. 실제 이용 기능인 지도 환승 버튼·시설 검색/필터는 목차와 구분해 유지한다.
- 말투는 자연스럽고 구체적인 한국어 해요체. 조사 메모·단답·번역체·추상적 추천 대신 어디로 가서 무엇을 하고 얼마를 내는지 연결된 문장으로 설명한다. 모든 문장을 ‘확인하세요’로 끝내거나 같은 조건을 반복하지 않는다. 외국어도 현지 사용자가 읽기 자연스럽게 작성한다.
- 가독성: 시로코처럼 본문에 충분한 여백을 두고, 긴 문단을 의미 단위로 나눈다. 기본 정보와 요금 비교는 표/정의 목록, 순서는 단계, FAQ는 질문과 답 카드로 정리한다. 본문 전체를 박스로 둘러싸거나 출처 링크를 매 문장마다 반복하지 않는다.
- 중요 정보는 짧은 구절에 볼드: 적용 대상·층/출구/승차 위치·시간·요금·필수 행동·예외 조건. 숫자만 강조해 적용 조건을 놓치게 하지 않는다. 문단 전체 볼드는 금지한다.
- 기존 사실·노선·항공사·연결 URL·공식 근거·예외 조건을 디자인이나 말투 변경 과정에서 삭제하지 않는다. 미확인 값·다른 장소 사진·가짜 지도·임의 요금은 만들지 않는다. 반복 출처는 하단에 모으되 문단별 근거 추적은 유지한다.
- 국가/언어별 페이지는 번역 복제가 아니다. 공통 규정은 공유하지만 항공사·노선·연락처·확인서·보험 정보는 해당 국가 시장 데이터로 구성한다. 다국어 공항 안내의 괄호 한국어 검수 해석은 원문과 분리하고 `airportKoreanReviewEnabled` 설정으로 일괄 제거 가능하게 유지한다.
- 완료 전 PC·모바일에서 여백, 표/카드, 지도·버튼, 가로 넘침, 실제 상세 링크를 확인한다. 정보성 글은 원문 조건·금액·시간·FAQ가 보존됐는지도 확인한다. 적용 없이 ‘시로코 기준 완료’라고 보고하지 않는다.

## 정보가 없는 항목은 표시하지 않는다

사용자 확정 지시: 모든 상세페이지는 기본 공통 템플릿을 사용하되, 해당 데이터에 정보가 없으면 그 부분은 화면에서 제외한다.

- null, undefined, 빈 문자열, 빈 목록, 미확인 값은 정보 없음으로 처리한다.
- 표의 값이 없으면 해당 행 전체를 제외한다. '미확인', '-', '정보 없음', '준비 중'으로 자리를 채우지 않는다.
- 카드·목록·사진·전화·주소·교통·요금·FAQ 등 모든 항목에 동일하게 적용한다.
- 섹션에 표시할 정보가 하나도 없으면 제목·설명·빈 영역을 포함해 섹션 전체를 제외한다.
- 목차와 페이지 내 이동 링크도 실제 표시되는 섹션만 포함한다.
- 관련 역·선착장·명소 링크는 연결 데이터와 대상 페이지가 있을 때만 표시한다.
- 도보 거리·시간처럼 일부 정보만 없다면 없는 값만 제외하고 확인된 연결 정보는 표시한다.
- 사진이 없으면 사진 영역과 빈 사진 안내를 제외한다. 다른 장소 사진을 대신 사용하지 않는다.
- 숫자 0과 boolean false는 정보 없음이 아니다. 무료 요금·불가 여부 등 의미 있는 값은 적절한 문구로 표시한다.
- 확인된 내용과 미확인 내용이 섞여 있으면 확인된 내용은 유지하고 미확인 부분만 제외한다.

기본 템플릿의 항목 구성은 공통으로 유지한다. 페이지별 표시 여부는 데이터에 따라 결정한다. 미확인 데이터는 내부 조사 기록에 남길 수 있으나 사용자 화면의 빈 항목으로 노출하지 않는다. 정보가 확보되면 같은 항목을 자동으로 표시할 수 있도록 한다.

적용 대상: ThaiLiveNow 명소·관광지·교통수단·노선·역·정류장·선착장 상세페이지.

## 페이지 유형별 고정 구조

### 교통 카테고리의 범위

교통 허브의 카테고리는 짧은 이용 안내 글 한 편으로 완료하지 않는다. 카테고리 → 전국/도시 실제 노선 지도 → 역·정류장·선착장 핀 → 개별 상세페이지 → 주변 명소·시설로 이어지는 서비스를 구현한다. 뮤즈는 공식자료 조사와 구조화 데이터 확보를 담당하고, Codex는 이를 가공하여 실제 사용할 수 있는 페이지를 완성·검수한다.

기차 카테고리는 태국 전국 철도 노선·역 위치를 실제 지도에 표시한다. 역 클릭 시 역 상세페이지에 연결한다. 역 상세 공통 구성은 다음과 같다.

1. 한국어 역명·공식 영어명·태국어명, 역 코드, 연결 노선과 역할.
2. 실제 지도, 위치·입구·역 연결 및 길찾기.
3. 기본 이용 정보: 역/매표소 운영시간, 전화, 주차·이용조건, 시설·접근성.
4. 열차 이용 정보: 행선·방향별 첫차·막차, 출발·도착/정차 시각, 운행일, 해당 날짜/요일의 정차 열차 수, 공식 시간표·예약 연결. 역 영업시간과 열차 운행시간을 구분한다. '하루에 몇 번'은 통과열차가 아닌 여객 정차 횟수인지 명시하고 양방향·요일·운행일을 구분해 중복 계산하지 않는다.
5. 표 구매 → 행선·승강장 확인 → 탑승 → 하차·환승 안내.
6. 주변 유명 명소·쇼핑몰·시설, 마지막 도보 경로·거리·시간과 내부 상세 링크.
7. 실제 이용 질문에 답하는 FAQ, 고유 SEO 제목·소개·내부 연결, 본문과 일치하는 구조화 데이터, 공식 근거 출처.

값이 없으면 임의로 만들지 않고 화면에서 제외하되, 요청된 필수 항목을 삭제한 채 작업 완료로 보고하지 않는다. 내부 수집 현황에는 미확보 항목과 조사 상태를 남겨 추가 조사한다.

철도·버스·보트는 각 수단의 정류 지점과 노선에 맞춰 같은 연결 구조를 적용한다. 택시·오토바이 택시·지역 교통처럼 고정 노선이 없는 경우에는 없는 노선을 만들지 않고 이용 지역·승차 지점·호출·요금·탑승 안내 중심으로 구성한다.

각 페이지는 하나의 중심 주제와 검색 의도를 정하고 아래 구조를 공통 컴포넌트로 관리한다. 자료 파일을 그대로 보여주는 것이 아니라 여행자가 이해할 수 있는 페이지로 가공한다.

- 도시 교통(예: 방콕 교통): 현지어명·영어명 제목 → 초행자 핵심 안내 → 실제 지리 지도·노선 필터·역 선택 → 대표 목적지와 이용 노선 → 표 구매·탑승·환승·하차 안내 → 노선별 상세 연결 → FAQ → 출처.
- 노선 상세(예: BTS 수쿰윗선): 제목 → 연결되는 주요 지역·명소 → 실제 노선 지도·정차역 → 이용 가능한 표·결제 → 방향 선택·탑승·환승·하차 → 주변 장소·역 페이지 → FAQ → 출처.
- 교통수단 이용 가이드(예: 태국 버스 타는 법): 제목 → 이용하기 좋은 상황 → 종류 비교 → 타는 곳 찾기 → 탑승·결제·하차 순서 → 실제 이동 사례 → 도시별 노선 연결 → FAQ → 출처.
- 명소 상세: 기존 명소 구성과 실제 교통 지도·가까운 역/선착장의 마지막 이동 안내를 유지한다.

실제 노선 지도는 출처가 확인된 좌표와 노선 형상을 사용한다. 임의 배열한 역·환승 도식을 실제 지리 지도의 대체물로 사용하지 않는다. 표는 비교용일 때만 사용하며, 좁은 열에서 장소명이 한 글자씩 깨지지 않도록 카드·가로 스크롤 등 문맥에 맞는 표현을 선택한다.

자료 수집·검수 상태와 개발 용어는 방문 안내 본문과 분리한다. 로컬 검토용 진행 표시는 별도 영역에서 제공할 수 있다. 제목·본문·관련 내부 링크·구조화 데이터는 같은 중심 주제에 맞춘다. 관련 질문은 실제 방문 의사결정에 필요한 정보로 답하며 키워드를 나열하지 않는다.

## 교통수단별 내용 분기 (사용자 확정)
공통 헤더·언어 선택·폭·글꼴·목차·지도/정보 카드·FAQ·출처 스타일은 고정한다. 각 수단의 본문과 데이터 항목은 실제 이용 방식에 맞게 다르게 구성한다. 모든 수단에 역/노선/고정요금 양식을 강제로 적용하지 않는다.
- 전철: 도시별 실제 노선·역 위치와 환승, 운영사별 표 구매·개찰구·방향·출구.
- 기차: 전국 운영 여객노선·역, 열차/좌석 종류·예매·역별 목적지 시간표·정차·시설.
- 버스: 시내/시외·일반/에어컨·운영사, 번호/정류장/터미널, 탑승·결제·하차.
- 보트: 강/섬/횡단페리 구분, 실제 수로와 선착장, 서비스별 정차·방향·승선·결제·하선.
- 택시: 미터/호출·승차장소·추가요금·목적지 전달·결제.
- 오토바이: 승차대/호출·요금표/합의 방식·헬멧·짐/인원·승하차.
- 툭툭: 전국 고정가격으로 안내하지 않는다. 탑승 전 목적지·인원·총요금 합의/흥정 방법을 설명한다. 쏭태우는 노선형 공유승차와 전세, 도시별 방식을 구분한다.
- 국내선: 현재 태국 국내선 운항 항공사를 공식자료로 조사해 항공사별 취항 공항/도시·예약·체크인·수하물·운임 조건을 연결한다. 국내선 비행과 공항→시내 교통을 구분한다. 운항 중단 브랜드를 현행 항공사로 소개하지 않는다.
- SEO/AEO/GEO: 메인 검색 의도에 답하는 제목·소개·소제목·FAQ와 지역/시설/교통 연결을 자연스러운 한국어로 작성한다. 연관어는 문맥에 맞게 쓰며 검색량/순위/노출 성과를 만들어내지 않는다.

## 루프탑 허브·상세페이지 (2026-10-13 확정)
도시 선택 → 해당 도시 실제 지도·검증 시설 핀·같은 도시 목록 → 핀/카드에서 시설 상세페이지. 도시별로 동일한 UI를 사용하며 다른 도시 시설을 섞지 않는다. 시설 좌표는 건물 위치임을 표시하고 입장층은 별도 안내한다.
