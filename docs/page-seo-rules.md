## 연관 페이지 연결 필수 적용 — 2026-10-17

페이지·데이터·HTML 신규 생성·공개 및 장소·URL·언어·공개 상태 변경 전에 [연관 페이지 연결·생성 검수 계약](INTERNAL-LINKING-CONTRACT.md)을 반드시 읽고 적용한다. 새 상세와 기존 상위·관련 페이지 양쪽의 초기 HTML 링크, 같은 시장 공개 정본, canonical·사이트맵, 문맥·PC/모바일을 같은 작업에서 검수한다. 기존 본문·확인일·검수 근거를 보존하고 자동화 미구현·수동 검수·실제 색인 상태를 구분한다.

## 페이지별 중심 질문과 사실

- 페이지마다 독자가 해결할 중심 질문 하나를 정한다. 대상 장소·도시·국가·여권과 방문/신청 목적을 구분한다. 주변 주제는 필요한 설명과 관련 링크로 연결한다.
- title·H1·description·본문·내부 링크·구조화 데이터는 같은 실제 내용을 설명해야 한다. 검색어를 넣기 위해 확인되지 않은 요금·일정·서비스·자격·평면도 등을 만들지 않는다.
- 한국 페이지는 한국 여권/시장에 해당하는 내용, 영어권 시장은 미국·영국·인도별 해당 조건을 사용한다. 언어와 국적은 같은 개념이 아니다. 국적 무관한 공통 규정은 포함할 수 있다.
- 검색 의도와 사실의 의미는 사람이 본문과 근거를 읽어 판단한다. 자동 태그 생성·단어 검사·pass 플래그를 내용 검수의 대체로 사용하지 않는다.

## 제목·설명·본문

- 제목은 해당 페이지의 대상과 핵심 질문을 구체적이고 간결하게 표현한다. 브랜드는 한 번만 표시한다. 모든 상세에 ‘태국 여행’이나 홈페이지 키워드를 반복해서 덧붙이지 않는다. 언어/시장 구분에 필요한 문구는 유지한다.
- H1은 공개 정보 페이지에 하나만 두고 중심 주제를 명확히 표시한다. 제목과 H1의 문구가 완전히 같을 필요는 없지만 다른 내용을 약속하면 안 된다.
- 설명은 실제 제공하는 정보와 중요한 조건을 자연스러운 완결 문장으로 요약한다. 홈페이지 설명을 상세에 상속하지 않는다. 제목을 설명 앞에 기계적으로 반복하지 않는다. 단순 글자 수로 문장을 잘라 적용조건/예외를 없애지 않는다.
- Google의 고정 글자 수 제한으로 60자/160자 등을 주장하지 않는다. 길면 사람에게 검토 경고를 주고 중심 정보와 조건을 보존해 다시 쓴다. 최종 검색 제목·스니펫은 Google이 다르게 표시할 수 있다.
- 본문은 제목이 약속한 질문에 먼저 답하고 기본정보·이용 방법·조건·예외·FAQ·관련 링크·공식 근거를 주제에 맞춰 연결한다. 빈 항목과 미확인 값은 노출하지 않는다.
- meta keywords는 Google 검색 순위에 사용되지 않는다. 새로운 페이지에는 만들거나 홈페이지 값을 상속하지 않는다. 키워드 나열 대신 제목·본문 정합성을 검수한다.

## URL·색인·공유·구조화 데이터

- canonical은 운영 도메인 https://thailivenow.com 아래 실제 대표 페이지의 절대 URL 하나다. 내부 링크/사이트맵/OG URL과 대표 경로를 맞춘다. 상세를 전부 홈 canonical로 보내지 않는다.
- 공개 정보 페이지는 기존 공개 정책에 따라 index,follow. 저장/비교 등 개인화 페이지와 확인된 중복 별칭은 noindex,follow 및 적절한 canonical. 준비 중/비공개 등 추가 제외는 페이지에 `<meta name="tln:indexing" content="noindex">`로 명시한다. 미확인 콘텐츠를 공개 완료한 것처럼 색인시키지 않는다.
- 기존 임시 robots 태그와 공통 정책이 충돌하지 않게 검사한다. 정책을 바꿀 때는 해당 페이지와 이유를 기록한다. noindex는 비공개 접근 제어 수단이 아니다.
- OG/Twitter 제목·설명은 페이지별 값을 사용하고 URL은 canonical과 일치시킨다. 사용권이 확인된 페이지별 OG 이미지를 지정했다면 보존한다. 지정 이미지가 없으면 공통 브랜드 이미지를 사용한다. 다른 장소의 사진이나 가짜 현장 사진을 넣지 않는다.
- 구조화 데이터의 제목·설명·FAQ·날짜·위치 등은 실제 화면/근거와 일치시킨다. FAQPage가 있다고 리치 결과가 보장되는 것은 아니다. 보이는 질문과 답을 바꾸면 데이터도 함께 바꾼다.
- hreflang은 실제 존재하고 언어/시장·동일 주제 연결이 맞는 페이지에만 사용한다. 번역되지 않은 상세를 다른 언어의 홈과 동일 상세처럼 묶지 않는다.
- 사이트맵에는 실제 대표 indexable URL만 포함한다. 별칭·개인화·noindex 페이지는 제외한다.

## 자동 적용 위치와 필수 검사

- `src/middleware.ts` → `src/lib/page-seo.mjs`: 정적 빌드와 로컬 응답에 공통 태그 적용. 이미 작성한 페이지별 title/description과 본문 요약을 사용한다. 기존 JSON-LD의 사실은 보존하고 WebPage의 기술 메타는 최종 canonical·제목·설명과 동기화한다. 페이지별 근거 검토 요약이 필요한 경우 `src/data/page-seo-overrides.json`에 명시하며 홈 키워드를 일괄 상속하지 않는다.
- `npm run build`: `npm run test:seo` 회귀 테스트 → Astro 빌드 → `scripts/audit-seo.mjs` 순서로 자동 실행한다. 새 파일·데이터 생성도 이 흐름을 사용한다. Astro만 호출했다면 같은 출력 폴더에 SEO 감사를 별도로 실행한다.
- 오류로 빌드 실패: 필수 메타 누락/중복/빈 값, indexable H1 누락/중복, 서로 다른 대표 URL의 중복 title, 같은 언어·시장 안의 중복 description, canonical 대상 누락/색인 별칭 충돌, OG 불일치, 잘못된 JSON-LD, 변환 중복 적용 문제.
- 사람의 재검토 경고: 긴 제목/설명, 남아 있는 keywords. 길이 경고는 순위·검색량·콘텐츠 부실의 판정이 아니다. 고유한 긴 공식 명칭은 사실을 지키며 판단한다.
- 전체 메타 목록은 `artifacts/seo-audit.json`에 기록한다. 기존 페이지도 전체 검사를 돌리고 발견된 문제를 고친다. 중복 제목은 보고만 하고 넘어가지 않는다.
- 새로 만든 페이지와 변경 페이지를 PC·모바일에서 확인한다. 링크·화면·본문/FAQ·국가별 조건·실제 이미지·키보드 동작은 관련 변경에 맞춰 검증한다.

## 완료 기록

작업마다 대상 URL/파일, 중심 검색 의도, 대상 국가·언어, 사실/본문 검토, 자동 검사 결과, 경고의 판단, 로컬 확인을 남긴다. ‘모든 페이지 SEO 완료’는 태그 검사와 전체 본문 검수를 구분해 보고한다. 상위노출·색인 완료·검색량·순위를 보장하거나 검증 없이 주장하지 않는다. 운영 배포는 사용자 승인 범위에서만 실행한다.

## 2026-10-14 사용자 확정: 검증된 자료를 받아 작성·유지보수한다

기존 본문과 사용자가 검증된 내용으로 제공한 새 원고의 사실·시간·요금·조건·예외·출처는 기준 자료로 받아들인다. 한국어·구성·제목·메타 수정 요청에서 공식 근거 재조사를 시작하지 않는다. 사실의 의미와 적용 범위를 보존한 전후 비교, 제목이 약속한 내용의 실제 본문 포함 여부, 자연스러운 문장과 화면 검증을 수행한다. 사용자 요청으로 새 사실을 조사하거나 모순을 해결하는 작업은 별도 범위다. 이 절은 앞의 사실 대조 지침을 자료의 의미·보존 대조로 적용하도록 명확히 한다.


## 2026-10-20 사용자 확정: 상세 저자와 공개 날짜·공유 이미지

최신 사용자 지시에 따라 공개 운영 배포일 및 배포일에서 유래한 자료 확인일·정보 업데이트 표시는 제거한다. 기존 배포일 상시 노출 요구보다 이 절이 우선한다. 운영 배포 JSON·서버 스냅샷·실제 자료 확인일·촬영 시각·재생 확인·콘텐츠 수정 기록은 보존한다. 실제 확인 기록은 날짜가 배포일과 같아도 제거하지 않으며 출처별 실제 날짜를 일반 페이지 날짜로 덮어쓰지 않는다.

모든 지원 언어 상세 H1 바로 아래에 현지 언어의 ‘글·해설: ThaiLiveNow’를 표시하고 author/publisher는 ThaiLiveNow 조직에 연결한다. 외부 미디어·데이터 주체는 기존 실제 제작자·제공기관을 유지한다. 공통 SEO·날짜 prepare·서버 및 클라이언트 날짜 경로에도 적용한다.

대표 공유 이미지는 장소와 일치하고 이용 근거가 보존된 사진을 사용한다. OG/Twitter 이미지·설명을 일치시키며 카메라 참고사진은 실제 카메라 화면과 구분한다. 사진이 없으면 브랜드 이미지와 예외 기록을 사용한다. `scripts/audit-detail-editorial.mjs` 및 이미지 근거 카탈로그 검사를 전체 빌드·정식 릴리스에 포함한다. 기존 본문·사실·URL·사진·원출처·검수 기록을 보존한다.
